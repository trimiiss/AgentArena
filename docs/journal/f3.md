# Journal F3: Containers and Kubernetes

Numbers below were measured on 6 November 2026 on the development laptop. Re-run the commands before submitting.

## 1. Çfarë ndërtova (what I built)

Every service has a non-root image with a pinned base, and Compose starts the whole stack with health checks. The Kubernetes manifests add probes, resource limits, autoscaling and a hardened security context. The namespace enforces the `restricted` Pod Security Standard. `scripts/deploy-kind.sh` creates a cluster and deploys everything with fresh random secrets.

## 3. Vendimet (decisions)

**Migrations in an init container.** Alternatives: a one-shot Job, or running them when the app starts. An init container blocks the pod until the schema is ready, and an advisory lock makes parallel replicas safe. Cost: a pod start takes a little longer.

**A single-node kind cluster.** Three nodes would be more realistic, but Docker has 7.7 GiB here and the full platform needs about 4 GB. Cost: pod anti-affinity and node failure cannot be tested.

**Kustomize with an overlay for secrets.** `k8s/` must apply on its own for the course check, using placeholders. Real values come from `infrastructure/kind/overlay`. Alternative: Helm, which is more powerful but adds templating that this project does not need.

**Liveness checks only the process, readiness checks the database.** If liveness checked the database, one database outage would restart every pod and make it worse.

## 4. Ku gaboi AI (where the AI was wrong)

Two cases, because they teach different things.

**A failed deployment was reported as a success.** The AI ran the deploy script through `| tail -40`, so the exit code came from `tail`. It reported exit 0 while no pods existed. Loading a multi-platform image into kind had crashed the script. Reading the log rather than the exit code caught it. The next attempt failed too: the AI had put the overlay inside its own base, and Kustomize rejects that as a cycle.

**The AI's first explanation for a slowdown was wrong.** Registration took 21 seconds on Kubernetes. The AI suspected Argon2 password hashing under the CPU limit. Measuring in the pod showed 0.2 s, so that idea was wrong, and optimising it would have achieved nothing. 21 s is the Windows TCP timeout (3+6+12 s): `localhost` tried IPv6 `::1` first, where nothing listens. Using `127.0.0.1` took 0.03 s.

Lesson: check the evidence before fixing anything, and do not trust an exit code that passed through a pipe.

## 5. Çfarë mbetet (what remains)

- PostgreSQL and RabbitMQ are single replicas with no backups. Production needs managed services or a three-node cluster.
- ingress-nginx has been retired upstream. A real deployment should move to Gateway API.
- Images are 395 MB. A slimmer base is possible, but this is not a bottleneck yet.
