# Journal F2: Communication

Numbers below were measured on 6 November 2026 on the development laptop. Re-run the commands before submitting.

## 1. Çfarë ndërtova (what I built)

Services communicate through REST with timeouts where they need an answer, and through RabbitMQ for everything else. Events go through a transactional outbox, and consumers are idempotent. Failed messages pass through retry queues of 1, 5 and 30 seconds, and then a dead-letter queue. Contract tests fail if an API or event drifts from its published schema. A run now flows from the API through the broker to workers and the evaluator.

## 3. Vendimet (decisions)

**RabbitMQ.** Alternatives: Kafka, NATS, Redis Streams. Executions are jobs that need per-message acknowledgement, delayed retries and dead-lettering, which RabbitMQ gives directly. Cost: replay is not available, and quorum queues use more disk. See ADR 0002.

**Outbox with at-least-once delivery.** The alternative, publishing after commit, loses events if the process dies between the two steps. Cost: up to 200 ms of extra latency, and every consumer must deduplicate. See ADR 0003.

**The database owns execution state.** RabbitMQ only carries work. A redelivered message cannot tell a dead worker from a slow one, so workers hold short leases in the database. Cost: a heartbeat write every 5 seconds per running execution. See ADR 0004.

**Events carry what the consumer needs.** `evaluation.requested` includes the transcript and the expected outcome, so the evaluator keeps working when other services are down. Cost: larger messages.

## 4. Ku gaboi AI (where the AI was wrong)

Consumers did not survive a broker restart. All 272 tests were green. The first chaos experiment restarted RabbitMQ during a run, and the run froze with 6 jobs dispatched and none running.

The queues held every message, which ruled out data loss. They also showed 0 consumers. The AI's `consume()` fetched the queue with `get_queue(ensure=False)`. A robust channel only restores queues it declared itself, so the connection came back and nothing resubscribed. Declaring the queue on the consumer's channel fixed it.

The logs showed a second bug on the same path. If a channel closed just after a handler succeeded, `ack()` raised, so a processed message took the retry path. It only looked harmless because deduplication hid it.

Lesson: durability and recovery are different properties. A message that is safe but never consumed is still an outage. Details are in [the experiment](../chaos/2026-11-06-broker-restart.md).

## 5. Çfarë mbetet (what remains)

- `processed_messages` needs pruning.
- Replaying a dead-letter queue is a manual step.
- One RabbitMQ user serves all services. Separate users would limit what a compromised service could publish.
