## 1. Çfarë ndërtova (what I built)

One GitHub Actions workflow runs lint, unit, contract and integration tests, and frontend tests and build. It then runs end-to-end and failure-injection tests on Compose, builds and scans each image, generates SBOMs, publishes to GHCR, deploys to kind and runs the smoke test. `scripts/smoke.sh` proves a full path from sign-up to a passing benchmark. Rollback was tested on a real broken release under traffic.

## 3. Vendimet (decisions)

**Tag images with the commit SHA, never `latest`.** Alternative: `latest` is simpler. But then a deployment does not say what it runs, and a rollback cannot name a target.

**Run Trivy and Syft from pinned images, not marketplace actions.** Alternative: `aquasecurity/trivy-action`, as most guides suggest. Its tags were hijacked in March 2026 (CVE-2026-33634), and Docker Hub images were hit days later, so a tag can point to different code tomorrow. Both images are pinned by digest. Cost: a few more lines of YAML, and pinned hashes must be updated by hand.

**Fail the pipeline on fixable HIGH and CRITICAL findings only.** Alternative: fail on everything. Findings with no available fix would block every build and train people to ignore the scanner. Cost: accepted risk on unfixed issues.

**One workflow rather than several.** Later jobs need earlier results through `needs`, and one graph is easier to read. Cost: a longer file.

## 4. Ku gaboi AI (where the AI was wrong)

The workflow looked finished and would have failed on its first run. Two faults only showed up by reasoning about the environment, because `actionlint` accepted both.

First, the AI called scripts directly with `run: scripts/smoke.sh`. On Windows, `git add` does not record the executable bit, so on the Linux runner each step would fail with "Permission denied". They now run through `bash`. The same cause affected the PostgreSQL init script. Without the executable bit, the entrypoint sources it instead of running it, so its `set -eu` would leak into the entrypoint. A subshell now contains it.

Second, the AI used `aquasecurity/trivy-action@0.33.1`, a mutable tag on an action with a known compromise (CVE-2026-33634). It looked like normal practice, so nothing flagged it. Pinning the Docker image by tag alone would not have been enough either.

Lesson: a linter checks syntax, not the environment. Ask what is different between where code was written and where it will run.
