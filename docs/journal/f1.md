# Journal F1: Architecture

Numbers below were measured on 6 November 2026 on the development laptop. Re-run the commands before submitting.

## 1. Çfarë ndërtova (what I built)

I defined the architecture of AgentArena, a platform that tests and benchmarks AI agents: C4 diagrams, ten ADRs, seven SLOs with numbers, a risk table and one OpenAPI contract per service. Five services answer on `/health`, each with its own PostgreSQL database and role. A first end-to-end run proved the design before the detail was written down.

## 3. Vendimet (decisions)

**A fifth service for identity.** The brief lists four services but also needs login and organizations. Alternatives: put accounts in the Agent Registry, or use an external provider. I chose a separate service because no domain service should own security. Cost: one more service to run. See ADR 0001.

**One PostgreSQL instance, one database and role per service.** Alternatives: one server per service, or schemas in one database. Five servers would not fit in 8 GB of Docker memory, and schemas make cross-service joins too easy. Cost: a shared point of failure locally. See ADR 0005.

**Deterministic scores.** An LLM judge would be quicker to set up, but it cannot give repeatable benchmarks. Cost: scenario authors must state exactly what good behaviour is. See ADR 0006.

## 4. Ku gaboi AI (where the AI was wrong)

The scoring design was wrong, and the tests did not show it. The AI's first version passed a scenario when a weighted average reached 0.7. All 10 end-to-end tests passed in 7 seconds, which looked too easy, so the actual numbers were printed.

Three failures had passed. In "Address change across turns" the agent never called the tool and only claimed success, and it scored 0.79. In "Two requests in one message" it did half the job and scored 0.74. In "Refund tool fails once" it ignored a failed call, said "Done" and scored 1.00, because the word "refund" counted as acknowledging the failure.

Latency and tone checks were lifting the average. The fix separates requirements, which can fail a scenario, from quality checks, which only lower the score. Failure handling now reads tool results rather than wording. Regression tests cover all three cases.

Lesson: passing tests only prove what they assert. Read the output.

## 5. Çfarë mbetet (what remains)

- Row-level security in PostgreSQL, as a second layer behind the application's organization filter.
- A retention job for `processed_messages` and transcripts.
- Key rotation for tokens and credentials is documented, not automated.
