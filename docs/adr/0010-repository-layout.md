# 0010. Repository layout follows the course checks where they differ from the brief

Status: accepted

## Context

The project brief proposes a layout, and says the professor's requirements take priority. The course's check scripts look for specific paths, and treat every folder under `services/` as a complete microservice.

## Decision

| Brief | This repository | Reason |
| --- | --- | --- |
| `shared/contracts/`, `shared/schemas/` | `contracts/` at the root | The checks look for `contracts/<service>.openapi.*`. |
| `infrastructure/prometheus`, `grafana`, `jaeger` | `observability/` | The checks look for `observability/` or `monitoring/`. |
| `infrastructure/docker/` | A Dockerfile in each service | The checks look for `services/<name>/Dockerfile`. |
| Not specified | `examples/sample-agent/` | Under `services/` it would count as a microservice. It is a demo that must share no code with the platform. |
| `shared/` | `shared/agentarena_common/` | One installable package for infrastructure code. |

## Alternatives

- **Follow the brief exactly.** The checks would fail, and the brief itself gives priority to the course.
- **Use symlinks for both layouts.** Fragile on Windows and confusing to read.

## Consequences

- Contract files are generated by `scripts/export_contracts.py`, and a test fails if they drift from the code.
- `k8s/` holds copies of a few config files, because Kustomize cannot read outside its own folder. They are small and change rarely.
